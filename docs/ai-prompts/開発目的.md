あなたは「Vertex FM Engine」という新規デスクトップアプリケーションを開発します。

添付・提示された「Vertex FM Engine 開発仕様書」をプロジェクトの基本仕様として扱ってください。

## 開発目的

Vertex FM Engineは、Claris FileMaker ProのXML Clipboardを扱うための開発支援IDEです。

単純なClipboard Managerではなく、

- FileMaker Clipboard取得
- FileMaker XML編集
- Clipboard Format判定
- XML Validation
- Clipboard履歴
- Collections
- Favorites
- XML Preview
- Structure表示
- Diff
- FileMaker Clipboardへの送信

を統合するアプリケーションを目標とします。

## 使用技術

以下を基本技術として使用してください。

- Tauri 2
- Rust
- Vue 3
- TypeScript
- Quasar Framework
- Monaco Editor
- SQLite
- Pinia

Windows版を最初に完成させます。

ただしOS依存処理をRust側で分離し、将来的にmacOS対応できる設計にしてください。

Linux対応は不要です。

## 重要な設計ルール

FrontendとOS依存処理を明確に分離してください。

想定構成：

```text
Vue / Quasar / TypeScript
        ↓
      Tauri
        ↓
       Rust
        ↓
 ┌──────┼─────────┐
Clipboard SQLite XML Core
        ↓
    FileMaker
```

Clipboard処理は、

```text
clipboard/
├─ mod.rs
├─ windows.rs
└─ macos.rs
```

のようにOS依存実装を分離してください。

macos.rsは初期段階ではstubでも構いません。

## FileMaker Clipboard

Windows版FileMaker Clipboardは通常のtext/xml Clipboardではありません。

Clipboard Dataは、

```text
4byte little-endian XML byte length
+
UTF-8 XML bytes
```

という構造です。

FileMaker Clipboard Formatとして現在確認されているもの：

```text
XMSC → Mac-XMSC
XMSS → Mac-XMSS
XMTB → Mac-XMTB
XMFD → Mac-XMFD
XML2 → Mac-XML2
XMFN → Mac-XMFN
XMTH → Mac-XMTH
```

未知のFormatも保存可能な設計にしてください。

enumのみで閉じた実装にしないでください。

## Windows Clipboard

可能な限りPowerShellを使用せず、RustからWindows Clipboard APIを直接利用してください。

FileMakerから：

```text
Clipboard Format
Raw Data
XML
```

を取得できるようにしてください。

FileMakerへ送信するときは、

1. XML UTF-8 encode
2. byte length計算
3. little-endian 4byte header生成
4. header + XML bytes
5. FileMaker Clipboard Formatへ登録

を実行してください。

## 作業方法

変更を実施する前に現在のRepository構造を確認してください。

既存コードがある場合は勝手に全面書き換えせず、その構造を理解してから変更してください。

各Phase終了時に、

```text
Completed
Changed Files
Architecture Decisions
Remaining Work
Next Recommended Step
```

を簡潔に報告してください。

まずは、

**Phase 1：プロジェクト骨格 + UIモックアップ再現**

まで実装してください。

このPhaseではFileMaker Clipboardの実処理はまだ不要です。

ただし後からClipboard Coreを追加しやすいインターフェースを先に定義してください。
